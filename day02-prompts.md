المهمة:

الـauthentication والـauthorization requirements.
أي API موجود حاليًا في المشروع.

استخدم هذه المعلومات لتحديد الـendpoints والـrequest/response structures المطلوبة.


القيود:
استخدم TypeScript.
التزم بالـarchitecture الحالية للمشروع.

استخدم RESTful conventions في تصميم الـendpoints.
طبّق validation على البيانات القادمة من المستخدم.
تعامل مع الأخطاء بطريقة موحدة.
طبّق authentication وauthorization إذا كان المشروع يحتاج إليها.
لا تكرر الـbusiness logic بين الـendpoints.



صيغة المخرج:
اعملي النتيجة بهذا الترتيب:

تصميم الـAPI والـendpoints المطلوبة.
Folder based structure المقترح.
الـdatabase/models المطلوبة.
كود الـAPI كاملًا.
Request/Response examples لكل endpoint.
طريقة التعامل مع authentication وauthorization.
طريقة اختبار الـAPI.





معايير القبول:
جميع الـfeatures المطلوبة لها endpoints واضحة.
كل endpoint يدعم الـHTTP method المناسب.
يوجد validation للـrequest data.
يوجد error handling واضح وموحد.
الـresponse structure موحد وواضح.
الـauthentication والـauthorization مطبقة على الـprotected endpoints.
الكود TypeScript بدون أخطاء.
يمكن للـfrontend استهلاك جميع الـendpoints بسهولة.


أسئلة التوضيح:
